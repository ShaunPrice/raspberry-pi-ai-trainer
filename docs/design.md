# Interface design

Audience: developers preparing custom models for a Hailo-equipped Pi. The page's job is to show project/data readiness and the next executable action.

Palette: ink #173343, steel #536975, lab background #edf3f6, paper #ffffff, instrument blue #175d91, attention copper #a34c15. Georgia display lettering gives the workbench an editorial title; system sans keeps forms familiar; monospace is reserved for target identifiers, statuses and raw records.

Layout: persistent project rail, target capability strip, paired project/data forms, then a full-width build-readiness panel. The signature is the target-to-pipeline relationship: selectable hardware determines what can proceed and why. Reviewed against the brief: avoid decorative performance counters or fictitious benchmark charts. All displayed results must come from service responses. Responsive layout collapses the project rail and forms; controls have labels and keyboard focus, status is announced, dynamic content uses textContent.
